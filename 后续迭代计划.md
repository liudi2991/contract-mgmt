## 1. 概述

### 1.1 当前 MVP 已交付基线

本次自动生成已落地：

- 工程：`docker-compose.dev.yml`、后端 Maven 骨架、前端 Vite 骨架、Flyway V1 全量建表脚本
- 后端模块：`auth / user / contract / payment / sysparam` 五个 Service+Controller
- 核心算法：**合同编号生成（Redis INCR + 启动校对）**、**回款核销（含 SELECT FOR UPDATE 与反向回退）**、合同状态机（业务触发版）
- 安全：JWT、登录失败锁定、RBAC、`SecurityHelper` 数据权限、`@Audit` AOP 异步落库
- 前端：路由守卫、布局、API 拦截器、登录 + 强制改密、合同 3 页（列表/表单/详情）、回款 3 页（计划/登记/列表）、首页驾驶舱

### 1.2 与 WBS 的差距

对照 `任务拆解WBS.md` 全表，本次未覆盖部分集中在以下四类：

| 类别 | 含义                                                       | 影响 |
| ---- | ---------------------------------------------------------- | ---- |
| A    | 业务功能缺口（合同附件 / 报表 / 导出 / 消息 / 定时任务）   | 影响上线可用性 |
| B    | 三个管理后台页（用户管理 / 系统参数 / 操作日志）           | 管理员无法在 UI 维护，需暂时走 DB |
| C    | 工程实践（单元测试、接口测试、e2e、性能/安全回归）         | 影响交付质量与回归能力 |
| D    | 上线运维（生产 Dockerfile、Nginx、CI/CD、备份、监控）      | 阻塞正式上线 |

下面按"上线必备 → 工程质量 → 体验增强 → 运维交付"四组排列，给每项**明确范围、可参考代码位置、验收标准与人天估算**。

### IT-1.3 定时任务（合同状态扫描 + 到期提醒）

| 字段       | 内容                                                              |
| ---------- | ----------------------------------------------------------------- |
| 关联 WBS   | T-3.2.4（每日扫描部分）、T-3.5.4（到期提醒）、T-3.5.6（容量监控） |
| 关联需求   | §3.2.5 合同状态、到期提醒                                         |
| 关联技术规格 | §5.4 状态自动流转、§5.5 提醒任务                                 |
| 现状       | 主类已加 `@EnableScheduling`；`ContractStatusService.evaluate()` 已实现；`Notification` 表与 Mapper 就绪；**定时任务类未创建** |
| 优先级     | P0                                                                |

**范围**

1. 新建 `scheduled/ContractStatusScanJob`：每天 00:30 扫描 `deleted=0 AND status NOT IN ('VOIDED','COMPLETED')` 的合同，调用 `ContractStatusService.evaluate()` 并落库；变更时写审计日志
2. 新建 `scheduled/ExpiryReminderJob`：每天 08:00，根据 `sys_param.reminder.days_before`（默认 `30,15,7,1`）扫描 expire_date，写入 `notification`（type=`REMIND_EXPIRE`），幂等键 `contractId + remindDay`
3. 新建 `scheduled/StorageMonitorJob`：每天 09:00，通过 `MinioClient` 累加 bucket 大小，超过 `sys_param.storage.warn.threshold` 时给所有管理员发 `notification`（type=`STORAGE_WARN`）
4. 全部使用 Spring `@Scheduled(cron = "...")`；建议加 `app.scheduled.enabled` 开关防止多实例并发；后续多实例上线可改 ShedLock + Redis

**实施提示**

```java
@Scheduled(cron = "0 30 0 * * ?")
public void scanContractStatus() {
    List<Contract> alive = contractMapper.selectAlive();
    for (Contract c : alive) {
        String newStatus = ContractStatusService.evaluate(c, LocalDate.now());
        if (!newStatus.equals(c.getStatus())) {
            c.setStatus(newStatus);
            contractMapper.updateById(c);
            // optional: audit / notification
        }
    }
}
```

- 提醒幂等：插入前 `SELECT 1 FROM notification WHERE biz_id=? AND biz_key=? AND DATE(created_at)=CURDATE()`，或建唯一索引 `(biz_type, biz_id, biz_key, scheduled_date)`
- 时区：`spring.jackson.time-zone=Asia/Shanghai`，cron 默认 Asia/Shanghai

**验收标准**

- 把测试合同 `expire_date` 改成"今天 + 7 天"，次日 08:00 能看到一条提醒（手工触发也可）
- 把测试合同 `expire_date` 改成昨天，次日 00:30 后状态自动变为 `EXPIRED`
- 同一合同同一天的同一提醒不会重复写入

**估算**：BE 2 人天

**范围**

1. 合同 / 回款列表导出（同步，≤ 1 万行）

   - `POST /api/exports`：写 `export_record` 状态 PENDING，返回 taskId
   - `@Async` 方法跑导出 → 上传 MinIO → 写 `download_url`
   - `GET /api/exports/{id}`：查询状态
   - 完成时写 `notification` 推送
3. 限频：管理员 6 次/小时（与 IT-1.7 共用 RateLimit）
4. 前端列表"导出"按钮 + 异步任务面板

**实施提示**

```java
@Async("exportExecutor")
public void runExport(Long taskId, ExportSpec spec) {
    try {
        File tmp = File.createTempFile("exp_", ".xlsx");
        exportToFile(tmp, spec);
        String objectKey = minio.upload(tmp, "exports/" + taskId + ".xlsx");
        exportRecordMapper.markDone(taskId, objectKey);
        notify(spec.getUserId(), "您的导出已完成", "/api/exports/" + taskId + "/download");
    } catch (Exception e) {
        exportRecordMapper.markFailed(taskId, e.getMessage());
    }
```

| 风险                                                | 等级 | 缓解措施                                                              |
